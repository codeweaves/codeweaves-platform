# Story 6.1: Chat Models & Module Setup

Status: done

## Story

As a **developer**,
I want ChatSession and ChatMessage database models with a NestJS Chat module,
so that we have the foundation to store chat conversations for analytics and power the n8n integration.

## Acceptance Criteria

1. **Given** the Prisma schema, **when** migration runs, **then** ChatSession and ChatMessage tables are created with all required fields and indexes.
2. **Given** a ChatSession model, **then** it includes: id, agentId (FK to Agent), sessionId (unique string passed to n8n), source (DEMO or WIDGET), status (ACTIVE or EXPIRED), createdAt, updatedAt, lastMessageAt.
3. **Given** a ChatMessage model, **then** it includes: id, sessionId (FK to ChatSession), role (USER or ASSISTANT), content (text), metadata (JSON — latency timestamps, token count), createdAt.
4. **Given** a new NestJS ChatModule, **then** it registers ChatController and ChatService and is imported in AppModule.
5. **Given** the ChatController, **then** it has a public route prefix `public/chat` (no auth required).
6. **Given** the packages/validation package, **then** Zod schemas exist for send-message input validation (chatInput: string 1-4000 chars, sessionId: optional string, agentId: UUID).

## Dev Notes

- Follow existing module patterns from `agents.module.ts` — modules live in `apps/api/src/modules/`, controllers in `apps/api/src/controllers/`, services in `apps/api/src/services/`
- The `sessionId` field on ChatSession is the string we pass to n8n for conversation memory tracking. It's NOT the database PK — it's a separate unique string (e.g., UUID generated by our backend)
- The `metadata` JSON field on ChatMessage stores latency analytics: `{ backendReceivedAt, n8nReceivedAt, agentRepliedAt, backendRespondedAt, responseLatencyMs }`
- ChatSource enum allows us to distinguish demo page conversations from future widget conversations for analytics
- Use `@Public()` decorator on the controller (same pattern as PublicAgentsController)
- Validation schemas go in `packages/validation/src/` following the existing pattern (see agent schemas)
